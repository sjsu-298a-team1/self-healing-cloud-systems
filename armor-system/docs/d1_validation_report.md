# ARMOR D1 — validation report

Engineering evidence for Linear 298-43. Everything below is regenerated by the tools in
`armor-system/data/tools/` and stored as JSON/CSV in `armor-system/data/manifests/armor_d1/`.
No model was run and no pickle was deserialized (see "Method"). D2 was not downloaded.

Labels: **VERIFIED** = read from released files by the tools; **CONFIG** = stated in the release's
config/README; **INFERRED** = deduced from verified facts; **UNKNOWN** = not determinable from the release.

## 1. Provenance and integrity

| Item | Value |
|---|---|
| Source | Zenodo record `21744694` ("ARMOR"), published 2026-08-01, CC-BY-4.0, concept DOI `10.5281/zenodo.19157588` |
| Archive | `ARMOR.zip`, 174,195,955 B, official md5 `b0f1068c2a32d76f30630c6217cbaab0` (live metadata matched before download) |
| Fetched | 62,077,283 B of the archive by HTTP range requests: `ARMOR/data/D1.zip` plus 15 small code/config/README files |
| Not fetched | `ARMOR/data/D2.zip`, all of `ARMOR/res/` (checkpoints, outputs). A 1.4 KB `config/D2.yaml` text file was fetched with the other configs |
| D1.zip | 62,606,253 B, CRC32 `bd23c9e8` (matches the official archive's central directory), sha256 `ef11fd2a…2f6c11` |
| Nested archive | `zipfile.testzip()` passed; 9 files extracted; no unsafe paths, symlinks or oversize members |

**Limitation (VERIFIED):** the official md5 covers the whole `ARMOR.zip`, which includes D2 bytes. Because D2 is
excluded by decision, the whole-archive md5 was **not recomputed**. Integrity rests on the member CRC32/size
values in the official central directory plus the nested-archive CRC test. Recorded in `checksums.json`.

Method: archive members are fetched with range requests and verified (`zip_safe.py`). Pickles are read by
`pickle_symbolic.py`, an opcode-level reader that records globals and calls as inert nodes and never imports or
calls them, so no pickle code can run. Tensor payloads are parsed as raw numbers (`torch_blob.py`).

## 3. Sample structure and features (VERIFIED)

- Each sample is `[timestamp (epoch seconds, UTC), DGL graph, float32 tensor 46 x 130]`. Timestamps step 60 s.
- **Channel grouping confirmed from `channel_dict.pkl` and `D1.yaml` `feat_span`:** metric 110
  (`kpi_container_*` indices 0-52, `system.*` 73-129), trace 9 (53-61: `duration`, `request_count`, `rpc_*`, `http_13`),
  log 11 (62-72: `severity_*`, `stack_trace`, warning counters, `at`). The groups are disjoint and cover all 130 channels
  (`channel_map.csv`).
- Representation: **precomputed numerical features, not raw telemetry.** Trace and log channels are aggregated
  statistics and counts; no raw spans, log lines or metric streams are in the release.
- NaN/Inf: 0 in all 7,200 tensors. Natural missingness is encoded as zeros: trace features are always zero for the
  6 `node-*` nodes, and log features always zero for 16 nodes (6 `node-*` plus the 10 `*2-0` services). Ten
  `*2-0` services also have all-zero trace rows in 2.5% of samples. Overall zero fraction is about 80%; 38 channels
  are constant.
- Graph: 46 nodes, directed edges stored as two int64 arrays per sample. Topology varies: train samples use 4
  distinct edge sets (268 edges each), test samples 11 (200-268 edges).
- Scaling (VERIFIED statistics, INFERRED recipe): values are bounded at +/-13.3791 = sqrt(179). Within 180-sample
  blocks, 83.3% of non-constant series are exactly mean 0 / std 1 (most of the rest have std about 1 with a small mean
  offset). Over the full 7,200-sample timeline, per-channel means are about 0 (|mean| <= 0.0009), while train alone
  or test alone are not centred. The exact recipe is UNKNOWN.

## 4. Labels and class distribution (VERIFIED)

- **Incident ground truth:** injection timestamps only (210 in `cases.csv`, 224 in `ad_cases.pkl`). There is no end
  time or duration. Any sample-level or interval label is **derived** (ARMOR scores AD with a +/-300 s tolerance).
- **`ad_cases.pkl` differs from `cases.csv`:** 21 AD timestamps have no case record (nearest case 463-2,246 s away) and
  7 cases are absent from the AD list (nearest AD event 463-2,468 s away). The meaning of the 21 extra events is UNKNOWN.
- **Fault type:** 15 fine-grained types map to **5 categories**, so the five-class target is reconstructable:
  Container Hardware (id 0), Container Network (1), Node CPU (3), Node Disk (4), Node Memory (5). Id 2 is unused.
  No case lacks a mapping.
- **Root cause:** `cmdb_id` has 47 distinct values; 136 cases name a graph node exactly, 74 (service-level cases) name a
  service without replica suffix (e.g. `frontend`), not a node. Failure levels: node 67, pod 69, service 74.

## 5. Split and leakage audit (derived from ARMOR code and VERIFIED data; official split untouched)

- **Time structure (VERIFIED):** `samples.pkl` is 5 contiguous days x 1,440 minutes, with 86,460 s gaps between
  days. `train_samples` (3,714) is the normal pool; `test_samples` (3,486) is 198 contiguous slices of 15 samples
  around the failures. Each case lies about 9.6 min (median 578 s) after its slice start and 4.7 min (280 s) before its end.
  Train and test have no shared timestamps.
- **FT/RCL split (ARMOR code):** cases by file order, first `int(0.6*210) = 126` train, last 84 test. The 84 test cases
  start 2022-05-06T17:30:08Z. The unit is the incident case. No windows overlap across the train/test boundary
  (gap 95,691 s); one consecutive case pair elsewhere has overlapping 359 s windows.
- **AD split (ARMOR code):** `split_ts = sorted(train+test)[int(0.6*N)] = 2022-05-06T16:00:00Z`. 2,879 samples and
  98 of the 224 AD events fall after it.
- **Findings that need decisions:**
  1. **Pretraining reaches into the held-out period (CONFIG + VERIFIED).** `D1.yaml` uses `train_samples_num: whole`;
     1,445 of the 3,714 normal samples are later than the AD split time. No held-out case window (`[ts-59, ts+300)`)
     contains a train sample, so there is no labelled-incident leakage, but test-period normal telemetry is used for pretraining.
  2. **Normalization statistics include test data (INFERRED).** Features are mean-centred only over the full
     timeline, so scaling used held-out samples. Raw D1 telemetry that would allow refitting was not verified to be available.
  3. **The "normal" pool may be contaminated (VERIFIED).** 161 train samples lie within 300 s of the 21 AD events that
     have no case record; none lie near a `cases.csv` case.
  4. **Event-level detection is supported only in ARMOR's definition:** a hit is an alert interval within +/-300 s of a
     timestamp; there are no true intervals.
  5. **Macro-F1 is supported** by the 5-class labels but is noisy (Node Memory has 4 test cases).
- Scaling inside ARMOR's code (audited: `create_dataloader_AR`, `armor_train.py`, FT/AD code): the dataloader applies no input scaling; the code's own scalers are FT's `StandardScaler` (fit on the 126 FT-train cases' pooled errors) and AD's z-scoring with statistics from train samples up to `split_ts`. Network layers (BatchNorm/LayerNorm) were not audited for leakage.

## 6. Model 1 data readiness: **CONDITIONAL**

| Question | Answer |
|---|---|
| A. Feature-level multimodal Transformer can consume D1? | **Yes.** Dense float32 46x130 tensors, no NaN, separable channel groups. Windows must stay inside contiguous runs: 6-step capacity is 2,785 windows in train (47 of 203 runs shorter than 6) and 2,496 in test; ARMOR's own 7-sample series (6 inputs + next-step target) gives 2,629 and 2,298. |
| B. Supervised detection target? | **Only derived.** Injection timestamps exist; end times do not. A labelling rule must be fixed and the 21/7 event discrepancy resolved. |
| C. Five-class failure target? | **Yes**, from `type_hash`/`type_dict`; counts above. |
| D. Normal periods support self-supervised pretraining? | **Yes, with a protocol:** 3,714 minutes (about 62 h), but restrict to samples before the cutoff and exclude the 161 suspect samples. |
| E. Meaningful 10/25/50/100% label budgets? | **Only partly.** 126 train cases give 13/32/63/126 labelled cases. Node Memory has 0.5/1.2/2.5/5 expected cases, so low budgets need stratified minimum-per-class draws, repeated seeds and variance reporting. |
| F. Safe modality masking? | **Yes** for group-level masking. Natural absence is already zero-filled, and zero equals the post-scaling mean, so add explicit missing indicators. |
| G. Preprocessing required | Decide the split protocol; build 6-step windows within runs; fix node order from `node_hash`; decide handling of 38 constant channels, the graph (optional) and the contaminated normals. |
| H. Still missing | Raw telemetry, incident durations, meaning of the 21 extra AD events, exact scaling recipe, how test slices were chosen. |
